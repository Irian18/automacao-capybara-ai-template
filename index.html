📖 Sobre o projeto

Este é um template de automação de testes end-to-end (E2E) construído com Ruby, Cucumber, Capybara, SitePrism e Cuprite. Ele foi pensado para ser adaptado a qualquer aplicação web, oferecendo uma base sólida de BDD, Page Objects e relatórios.

O diferencial está nas camadas opcionais de inteligência artificial: Self Healing Locators, que corrige seletores automaticamente quando a interface muda, e RAG, que busca contexto nos Page Objects para enriquecer o prompt enviado ao modelo de IA.

Por padrão, ambos os recursos estão desabilitados — basta usar os perfis cucumber -p self_healing e/ou cucumber -p rag quando quiser ativá-los.

⚡ Funcionalidades

🧠 Self Healing Locators

Quando um elemento não é encontrado, a IA propõe um novo seletor com base na DOM atual. Todas as alterações são registradas em locator_history.json para auditoria.

IA Autocorreção Opcional

🔍 RAG — Retrieval Augmented Generation

Indexa os arquivos de features/pages e os utiliza como contexto extra no prompt, ajudando o modelo a sugerir seletores mais precisos e alinhados ao padrão do projeto.

Contexto Page Objects Opcional

🥒 BDD com Cucumber

Cenários escritos em Gherkin, legíveis para times técnicos e de negócio, com suporte a tags, hooks e fixtures customizadas.

Gherkin Cucumber Padrão

📄 Page Objects com SitePrism

Organização da suíte com Page Object Model e DSL do SitePrism, tornando os testes mais reusáveis e fáceis de manter.

SitePrism POM Padrão

📊 Relatórios Allure

Geração automática de evidências: screenshots, vídeos, traces e logs de falha anexados a cada cenário no Allure Report.

Allure Evidências Padrão

🌐 Drivers flexíveis

Suporte a Cuprite (Chrome headless via CDP) e Selenium WebDriver, configuráveis por perfis no cucumber.yml.

Cuprite Selenium Padrão

🏗️ Arquitetura do fluxo

O fluxo de execução é simples e previsível. Sem os perfis opcionais, o projeto funciona como uma suíte de testes E2E tradicional. Com os perfis, a IA entra em ação apenas quando necessário.

Cenário Cucumber │ ▼ Page Object (SitePrism) │ ▼ Capybara + Driver │ ├─ Elemento encontrado? ── Sim ──▶ Continua o teste │ └─ Não ──▶ [Self Healing] IA analisa a DOM │ ├─ [RAG] Contexto de features/pages injetado no prompt │ ▼ Novo seletor sugerido │ ▼ Histórico salvo em locator_history.json │ ▼ Teste continua com o novo locator

🚀 Como usar

Instale as dependências, configure o .env e execute os cenários com o perfil desejado.

# Instalar dependências bundle install # Copiar e configurar variáveis de ambiente cp .env.example .env # Execução padrão (Self Healing e RAG desabilitados) bundle exec cucumber # Apenas Self Healing habilitado bundle exec cucumber -p self_healing features/specs/self_healing/login_self_healing.feature # Self Healing + RAG habilitados bundle exec cucumber -p self_healing -p rag features/specs/self_healing/login_self_healing.feature # Gerar relatório Allure allure serve report/allure-results
